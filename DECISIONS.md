# Fiche de décisions

| Choix | Options envisagées | Choix retenu et justification | Validé par l'auxiliaire (date) |
|---|---|---|---|
| Domaine | Sport, jeux vidéo, blackjack | **Blackjack.** Nous avons déjà un agent qui y a joué des milliers de mains ; l'application répond à une question simple pour un non-informaticien : « vaut-il mieux tirer ou rester ? ». | Non validé |
| Jeu de données | 1) Rejouer l'agent pour exporter chaque main ; 2) jeu Kaggle « 50 Million Blackjack Hands » (CC0) ; 3) la table sauvegardée par l'agent (`agent_v3_model.bin`) | **La table de l'agent.** Ce sont les vrais résultats obtenus contre le serveur (4 181 décisions), publiés sous CC0 dans le dépôt `blackjack-agent`. Option 1 impossible : le serveur n'existe plus. Option 2 écartée : il aurait fallu reconstruire chaque décision à partir de séquences d'actions, pour 3,9 Go de données. Limite : statistiques agrégées, l'ordre des parties est perdu. | Non validé |
| Conversion des données | Décoder avec Elixir puis convertir ; tout faire en Python | **Python seulement** (`outils/extraire_donnees_agent.py`) : un seul langage dans le projet, et le CSV se régénère avec une commande. Vérifié : même résultat que le décodage avec Elixir (678 situations, 4 181 décisions). | Non validé |
| Cible | L'action de l'agent (tirer / rester) ; le résultat de la main (victoire / défaite / égalité) | **Le résultat de la main.** Prédire l'action reviendrait à imiter l'agent, erreurs comprises. En prédisant le résultat pour « tirer » et pour « rester », l'application peut conseiller l'action la plus favorable. | Non validé |
| Variables du modèle | Toutes les colonnes ; seulement ce que l'utilisateur peut connaître | **Score du joueur, carte du croupier, As souple, cartes de valeur 10 visibles, action.** `cartes_utiles` et `cartes_bust` sont retirées : l'utilisateur ne peut pas les connaître sans compter les cartes du paquet. | Non validé |
| Nettoyage | Garder toutes les lignes ; retirer les lignes impossibles | **Retirer les lignes impossibles** : score du joueur au-delà de 21 (3 lignes : mains déjà perdues), valeurs manquantes, catégories inconnues. Les doublons sont gardés : deux mains identiques sont des observations légitimes. | Non validé |
| Métrique | Exactitude ; F1 macro ; log loss | **F1 macro et log loss.** Les classes sont déséquilibrées (57 % défaites, 36 % victoires, 7 % égalités) : l'exactitude seule récompenserait un modèle qui ne prédit jamais « égalité ». La log loss vérifie que les probabilités affichées sont fiables. | Non validé |
| Référence (baseline) | Prédire toujours la classe majoritaire ; prédire au hasard | **Classe majoritaire** (`DummyClassifier`), avec la fréquence de chaque classe comme probabilités : le modèle doit faire mieux que « toujours défaite ». | Non validé |
| Modèle | Régression logistique ; arbre de décision ; forêt aléatoire | **Forêt aléatoire**, comparée à la régression logistique sur la même séparation (graine 42). L'effet du score n'est pas linéaire (rester à 16 est mauvais, rester à 20 est excellent), ce qu'une forêt capte mieux. | Non validé |
| Interface | Tkinter ; Streamlit ; Gradio | **Streamlit** : peu de code, champs et graphiques Matplotlib intégrés (`st.pyplot`), lancement local simple. | Non validé |
